\section*{Executive summary}
For each detector, ingest calibrations and raw planes once, scan-correct,
subtract the supplied master from flats, trim, and retain one processed cube.
Create a robust-fit BPM if no input BPM is supplied; then measure linearity
ROIs and direct sites from the same cube. Release it before the next detector.
Linearity is measurement only; no response correction or gain conversion is applied.

\section*{Terminal usage}
Run from orchestration. The launcher admits metadata by default; add
\texttt{--execute} to process. It generates frozen native bindings and sets
niceness to at least 10. Project TOML supplies raw, calibration, reduced, work
and log roots. Use a fresh empty directory for the recipe's \texttt{run}.
\begin{verbatim}
python /path/to/tools/run-bpm-linearity.py --config RECIPE.toml
python /path/to/tools/run-bpm-linearity.py --config RECIPE.toml \
    --execute --qc false
\end{verbatim}
The underlying native command takes already generated bindings:
\begin{verbatim}
nice -n 10 mefpp_bpm_linearity_recipe cal bpm-linearity \
    --config RECIPE.toml --bindings NATIVE.toml [--qc true|false]
mefpp_bpm_linearity_recipe --help
\end{verbatim}
\begin{tabular}{p{.25\linewidth}p{.68\linewidth}}
\textbf{CLI option} & \textbf{Meaning / default}\\\hline
\texttt{--config FILE} & Required recipe TOML (launcher and native command).\\
\texttt{--execute} & Launcher only; absent means metadata admission, no reduction.\\
\texttt{--bindings FILE} & Native only; required frozen bindings from the launcher.\\
\texttt{--qc true|false} & Optional override; CLI $>$ recipe \texttt{qc} $>$ true.\\

\end{tabular}

\section*{Processing and populations}
A supplied master must match the archived scan/trim/stack configuration and
reside under the calibration root. A supplied BPM is loaded once and skips
creation, explicitly logged. With \texttt{input\_bpm="omitted"}, its historical
lineage remains intact but it is absent from current inputs. Previously admitted
direct samples must remain exact; newly admitted samples are reported separately.
ROI populations may increase. A generated candidate is never fed back into
this run's measurement mask.

For frame $f$ and raw row $y$, sort enabled scan values $v_{f,y,(k)}$ and reject
$l$ low and $h$ high reads:
\begin{align}
O_f(y)&=\operatorname{pix}\left[\frac{\sum_{k=l+1}^{n-h}v_{f,y,(k)}}{n-l-h}\right],\\
U_f(x,y)&=\operatorname{pix}[D_f(x,y)-O_f(y)],\\
S_f(p)&=\operatorname{pix}[U_f(p)-B(p)]\quad\text{(flats only)}.
\end{align}
Scan summation/division use double precision; $\operatorname{pix}$ converts to
native \texttt{pixelvalue}. Preserve both subtraction roundings. There is no
new scan fit or smoothing. Trim coordinates are FITS 1-based inclusive; active
row $j$ maps to raw row $j+y_{\min}-1$. The master receives no further scan
correction. Bias-role frames have no master subtraction. Active BPMs do not
mask electronic scan reads.

The common ROI population $\mathcal P$ passes the declared input mask,
finite-value and raw-saturation checks in both flats and both reference biases.
The saturation limit is an explicit processing control (OCAM: 65534 ADU).
For $N=|\mathcal P|$:
\begin{align}
\overline S_i&=N^{-1}\sum_{p\in\mathcal P}S_{ip}, &
s_i^2&=\frac{\sum_{p\in\mathcal P}(S_{ip}-\overline S_i)^2}{N-1},\\
d_p&=\operatorname{pix}[S_{1p}-S_{2p}], &
s_d^2&=\frac{\sum_{p\in\mathcal P}(d_p-\overline d)^2}{N-1}.
\end{align}
Scatter is unavailable for $N<2$. Corrected counts must equal admitted raw
counts. Transports retain member variances, difference variance and $s_d^2/2$;
spatial scatter is not a noise model or a fitting weight. Units remain ADU
and ADU$^2$; covariance and master variance are unavailable.

\section*{Candidate BPM and response limits}
The existing robust fitter in \path{mefpp2/src/iproc/detector_response.c}
classifies normalized pixel response $R$ using \texttt{MEF.BPM.LGAINTHR} and
\texttt{MEF.BPM.HGAINTHR}. Recipe \texttt{response\_low/high} override these
for the current run only; the input master's original snapshot is preserved.
$R\leq\mathrm{low}$ sets reason 4, $R\geq\mathrm{high}$ sets reason 8:
unflagged response lies strictly inside the limits. The existing native configuration stores limits in float32. These ratios are
\emph{dimensionless response}, not gain in electrons/ADU. Other reason bits
and robust-fit arithmetic are unchanged.

Reference ROIs, acquisition mode, usable signal range, pair mismatch and
coverage are saved with suitability assessments. Failed suitability does not
abort the subsequent measurements or establish scientific acceptance.
A zero reason byte means no detected reason, not certification.

\section*{Native recipe and source map}
The entry point \path{mefpp2/ins/mef/recipes/mefpp_bpm_linearity.c} follows
\path{mefpp_bias.c}: initialize/start; prepare/admit/begin; detector loop;
verify/publish/complete; common failure cleanup. Source landmarks:
\begin{enumerate}
\item \texttt{BPM-LINEARITY-ADMISSION}: \path{mef_bpm_linearity_config.c},
\path{mef_bpm_linearity_inputs.c}, \path{mef_bpm_linearity_bindings.c}.
Validate project roots, ordered bindings, frozen configurations and dependencies.
\item \texttt{BPM-LINEARITY-DETECTOR-LOOP}: \path{mef_bpm_linearity_process.c}.
\texttt{BPM-LINEARITY-INGESTION}: \path{mef_detector_cube.c} owns loaded
calibrations, raw/active planes and row traces; services borrow them.
\item \texttt{BPM-LINEARITY-CANDIDATE}: \texttt{mef\_bpm\_command\_from\_cube};
\path{mef_cal_bpm.c} and \path{detector_response.c} own fitting.
\item \texttt{BPM-LINEARITY-MEASUREMENTS}:
\path{mef_linearity_prepare_from_cube}, \path{mef_linearity_pairs.c}
and \path{mef_linearity_prepare.c}; row arithmetic uses
\path{mef_overscan_correction_traced} and difference statistics use
\texttt{image\_pair\_stats\_checked}.
\item \texttt{BPM-LINEARITY-PUBLICATION} and
\texttt{BPM-LINEARITY-PRESERVATION}: \path{mef_bpm_linearity_products.c},
\path{mef_bpm_linearity_hash.c}, shared native ASDF writer and MEF assembly.
\end{enumerate}
C helper files above reside under \path{mefpp2/ins/mef/common}, except the
image statistics/fitting kernels under \path{mefpp2/src/iproc}.
Pycavi's \path{pycavi_bpm_linearity_native_recipe.py} admits metadata,
invokes one native command and independently reads saved products. It contains
no detector processing loop. No Python pixel reduction or ASDF writer substitutes
for the native producer.

\section*{Products and verification}
Each detector retains preparation ASDF with input/HDU identities, native
measurements, traces, effective configuration, original dependency graph and
availability flags. Newly created BPMs have FITS, ASDF and logs. Final MEF/ASDF
assembly includes only newly created BPMs; an all-supplied-mask run has no new
BPM MEF. The manifest reports completion for inspection, not scientific approval.

Raw observations, calibrations and historical ASDFs are unchanged. Image planes
are loaded/corrected once numerically; whole-file preservation SHA256 passes
still read inputs before and after the batch. Saved readers require neither
raw pixels nor native execution. A zero native exit, completion receipt and
independent saved-product checks are required before acceptance.

Qualification uses tiny analytical scan/ROI fixtures, borrowed-cube ownership
checks, exact saved-product comparison and independent native-ASDF readers.
The supplied-mask CCD65 path passed Mac comparison. New recipe controls and
explicit archived-mask omission require their Mac gate before engine selection.
The stopped 32-detector run is preserved. Physical linearity correction,
cross-talk and uncertainty modeling remain deferred. Scientific design:\par
\path{docs/developer/design/linearity-preparation-overscan-asdf-v1.md}.\par
Coordinator design: \path{docs/developer/design/common-recipe-coordinator-v1.md}.
