\section*{Executive summary}
For each detector the native coordinator reads its input image planes and supplied
calibrations once into an owned cube. It applies row scan correction, supplied
master-bias subtraction and trimming once, preserving the existing arithmetic.
BPM fitting and linearity measurements borrow the same corrected planes.

A supplied input BPM skips candidate BPM creation, with an explicit log entry.
Recipe input-mask omission enables the existing robust response fitter to create
a candidate BPM FITS/ASDF before linearity ROI and direct-site measurements.
The admitted mask stays fixed for measurement populations. Pair consistency
and signal coverage are reported suitability assessments; failure does not
suppress the remaining measurements or certify the candidate.

The recipe and command accept \texttt{qc = true/false} and
\texttt{--qc true/false}. QC defaults to true. False suppresses optional full-frame
BPM QC and MAD calculations; requested ROI signals, variances, populations,
traces and provenance remain available. It does not bypass structural validation.
Linearity characterization is measurement only: no correction or gain conversion
is applied. Cross-talk remains outside scope.

Project TOML owns raw, orchestration and reduced roots. Raw observations and
calibrations remain unchanged. Products and working evidence reside below
reduced. Per-detector measurement ASDFs are always published; final BPM MEF/ASDF
assembly includes only newly created BPMs. An all-supplied-mask run has no new
BPM MEF. A zero reason byte is not certification.

The supplied-mask shared-cube path passed exact CCD65 checks on the Mac.
Explicit archive-mask omission has Linux numerical/ownership checks; its Mac
ASDF and real-data gates remain pending. Full-file SHA256 preservation passes
still read shared inputs before and after the batch: the numerical stages are
read-once; total integrity I/O is not yet fused with ingestion.

\section*{Explicit input BPM selection}
The recipe's preparation table selects the current mask policy:
\begin{quote}\small\ttfamily
[preparation]\par
input\_bpm = "omitted"
\end{quote}
The default is \texttt{archived}: use the mask named in the historical selection
and skip new BPM creation when that mask is supplied. Explicit \texttt{omitted}
selects no current BPM and enables robust candidate creation, even when the
historical archive used a mask. Detector/processing TOMLs, raw frames, archived
sample records and the supplied master are preserved. A mask previously used
in constructing that master remains part of its historical lineage; it is not
an additional current calibration. Remove unused mask-copy bindings from the
new recipe. The omitted mask is neither loaded nor included in current image
fingerprinting passes.

The processing TOML's encoding and polarity govern supplied masks. Explicit
recipe omission overrides only current mask participation. The source graph,
recipe policy, effective selection, current calibration bindings and native
transports are retained as provenance. Saved readers verify their agreement.
No generated candidate is fed back into the same run's ROI measurements.

Omission can increase ROI populations and change their moments. Exact replay
of all historical measurements is therefore not an acceptance requirement for
this mode. Direct sites retain their identities, exposure times and coordinates.
Every previously admitted direct-site value must remain exact. Previously
unavailable sites may become admitted; readers return their actual current
native values and report their count separately. They never fill current
measurements from the historical table. Native finite-value and saturation
checks remain in force; no fitting thresholds or population cuts are relaxed.

The focused fixture includes a historically masked direct site. It checks that
80 formerly admitted samples remain exact, 20 become available after explicit
omission, and all historical artifacts remain unchanged. Real-data acceptance
of this mode is a separate step.

\section*{Exact row correction and arithmetic}
For raw frame $f$, raw row $y$, and the $n$ enabled scan values sorted in
ascending order, the existing trimmed-mean routine returns
\begin{equation}
O_f(y)=\operatorname{pix}\!\left[
 \frac{\sum_{k=l+1}^{n-h}v_{f,y,(k)}}{n-l-h}\right].
\end{equation}
The sum and division use double precision; $\operatorname{pix}$ converts to
the native \texttt{pixelvalue} type. Low/high rejection is $l=h=10$ in the
selected OmegaCAM profile: 43 reads retain 23, and 44 retain 24. No sigma
clipping, smoothing, row fitting, endpoint extrapolation or global-level
replacement is introduced. First and last raw rows use their own scan samples.
The active-pixel BPM is not applied to electronic scan reads.

The native stages are
\begin{align}
U_f(x,y)&=\operatorname{pix}[D_f(x,y)-O_f(y)],\\
S_f(p)&=\operatorname{pix}[U_f(p)-B(p)]\quad\text{(flats only)}.
\end{align}
The trim uses inclusive FITS coordinates after scan subtraction. An active
row $j$ maps to raw row $j+y_{\min}-1$. Preserve both native roundings: do not
merge the subtractions. A supplied master is already scan-corrected and active;
it is subtracted once and receives no second scan correction. Bias-role frame
preparation has no master subtraction. The existing bias service performs
frame admission and stacking; this increment does not change its median or
rejection policy. The recipe verifies master configuration, source memberships and lineage
before reuse; compatibility is not inferred from pixel values.

\section*{Corrected ROI statistics and populations}
The paired service first reuses the unchanged raw-pair measurement service.
For each configured ROI it uses the common population $\mathcal P$ admitted
by the declared BPM and finite/raw-saturation checks in both flats and both
raw biases. The raw saturation boundary remains 65534 ADU. Pair members retain
their original identity, HDU, input index and exact duration.

For corrected member values $S_{1p},S_{2p}$, let $N=|\mathcal P|$. The services
retain ordinary means and sample scatter of each member and their difference:
\begin{align}
\overline S_i&=N^{-1}\sum_{p\in\mathcal P}S_{ip},\\
s_i^2&=(N-1)^{-1}\sum_{p\in\mathcal P}(S_{ip}-\overline S_i)^2,\\
d_p&=\operatorname{pix}[S_{1p}-S_{2p}],\qquad
s_d^2=(N-1)^{-1}\sum_{p\in\mathcal P}(d_p-\overline d)^2.
\end{align}
Difference pixel arithmetic follows \texttt{image\_pair\_stats\_checked}.
The native result stores standard deviations and availability; the native TSV transport stores their squared values and $s_d^2/2$ with explicit
definitions. For $N<2$, sample scatter is unavailable, not zero. A corrected
nonfinite value cannot silently remove an otherwise admitted measured pixel:
all three corrected population counts must equal the raw count.

Spatial scatter and difference scatter are diagnostic quantities, not assigned
independent weights. The shared master cancels algebraically in differences,
subject to native rounding. Raw bias-only RON and raw gain diagnostics retain
their original definitions. No uncertainty model or physical response is
estimated. ROI means remain distinct from the direct physical pixel samples
required by the later nonlinear model.

\section*{Recipe and immutable ASDF boundary}
\texttt{pycavi\_linearity\_recipe.preparation\_dependencies} reads the supplied
TOMLs and preserved sample/master QC graph. It requires exact scan, trim and
stack compatibility with the master snapshot and matches original identities,
HDU bindings, accepted/rejected memberships and readout. Legacy header fields
travel through a generated native compatibility TOML; they are not scientific
configuration overrides. Historical bias QC may have null image digests; the
completed bias execution receipt then supplies those fingerprints explicitly.

\texttt{prepare\_detector} fingerprints input images before native processing,
checks them again afterward, and freezes metadata and executable identities.
\texttt{mefpp\_linearity\_prepare\_command} reads every bias for ordered traces,
then streams flat pairs through \texttt{mef\_linearity\_from\_files}, using the
qualified preparation service and the existing direct-pixel extraction. It
reuses the existing master and never rebuilds it. Direct-pixel values are replay
checks against the preserved archive, not substitutes for full ROI measurements.
No separate singleton extraction campaign is required.

The recipe envelope references a project TOML in orchestration. That project
owns the raw, calibration, output, work and log roots. Observations remain
read-only in raw; existing calibrations are read-only dependencies below
reduced/cal. Controls and metadata requests stay in orchestration, and all
products, working files, logs and execution receipts stay below reduced.

With \texttt{publication = "native"}, the command retains only small ROI
metadata between pairs. \texttt{mef\_linearity\_archive\_add\_pair} copies the
already measured means and variances before the pair's image owners are
released. \texttt{mef\_linearity\_archive\_table} restores original flat-list
and configured ROI order and writes the exposure table exclusively. The
shared \texttt{mef\_product\_qc\_write} validates and publishes ASDF using the
same qualified C library as bias and BPM. This is an explicit table product:
application schema 2.0.0, ASDF standard 1.6.0, no invented image HDU. Existing
MEF and primary-image publication retain their separate layout checks.

The native ASDF contains typed exposure measurements, input identities, original
indices and source HDUs, calibration bindings and the exact native transports.
Those transports preserve raw diagnostics, pair differences, populations,
ordered row-correction traces and direct-site samples without repeating an
estimator. All biases are used for scan traces; their separate accepted/rejected
membership in the earlier master remains explicit in the source-binding and
trace evidence. The native context declares unavailable absolute noise/covariance
and an unperformed physical fit. No linearity or cross-talk correction is applied.

Python admits and freezes existing dependency metadata, copies the preserved QC
graph and verifies the completed native archive. It does not complete measurements
or write the new ASDF. The former Python publisher remains available explicitly
as a compatibility/reference path. Older recipe envelopes without a publication
field retain that path; the new example selects native publication.

\texttt{pycavi\_linearity\_native\_archive.read\_product} checks the local
schema, producer, configuration, detector/input/calibration bindings, frozen
relative dependency graph and equality of typed measurements with saved native
transports. Relocation needs neither raw images nor the native working directory.
The modelling accessor refuses to imply that missing uncertainty inputs are
ready for a fit. Original archives remain immutable, and outputs cannot be
reused or overwritten. Native preparation publication and its complete recipe
envelope require the focused Mac gate; observational acceptance remains pending.

Independent tiny FITS tests cover shuffled HDUs, known row ramps and ROI
moments, all ten bias memberships, original direct-site values, duplicate and
resource refusals, source preservation, ASDF roundtrip and relocation without
native files. Focused file-adapter allocation controls and the unchanged
singleton command check shared interfaces. None is scientific acceptance of
observational calibration or a general dependency memory-safety claim.

\section*{Combined detector characterization}
The combined recipe uses these entry points:\par
\texttt{pycavi\_bpm\_linearity\_plan.admit}\par
\texttt{pycavi\_bpm\_linearity\_recipe.execute}\par
One TOML references the
project roots, qualified native executables, detector/processing TOMLs and each
detector's preserved sample/master dependencies. BPM acquisition limits, output
mode and named reference ROIs are explicit; the coordinator supplies no new
scientific defaults. The source configuration and coordinator implementation
hashes are retained in the joined manifest.

All dependency metadata is admitted before image processing. Each detector is
processed serially: native linearity preparation first, then native BPM
characterization. Both use the admitted prior mask and master. The newly derived
BPM remains a candidate; it is never fed back into the same measurements.
The native routines retain their estimators, masks, populations and array
arithmetic. The coordinator performs no pixel computation or ASDF writing.
Native product companions remain together; process console logs use the project
log root. Execution requires niceness at least 10.

\texttt{BatchInputs} fingerprints each unique image once before and once after
the batch. Individual stages check file identity, size, modification time and
mode against that frozen baseline. The final byte digest is checked even when
those metadata fields are unchanged. This avoids rehashing shared multi-extension
raw files for every detector. Child receipts explicitly defer batch preservation;
the completed parent manifest resolves that check. Native source/binary and
configuration identities are checked independently.

The existing input-plane ceiling is checked for the BPM stage from the declared
raw geometry, flat count and two active calibration planes. This is a loaded-input
budget, not an RSS claim or a new bound on the existing kernel's scratch owners.
One native operation and one detector are active at a time; the coordinator holds
no detector cubes. The linearity service retains its existing working-pixel limits.

The manifest is published exclusively after source verification. Without an
assembly section its scope remains \texttt{detector\_characterization}, with
final MEF state \texttt{not\_assembled}. With an explicit assembly executable,
source revision and reference detector, the scope is \texttt{bpm\_linearity}
and final MEF state is \texttt{assembled}. Scientific acceptance remains false.
The native assembler requires common ordered flat inputs. Each detector retains
its admitted master and prior mask; separate calibration files are supported.

\section*{Final BPM MEF and QC publication}
The standalone assembly command is \texttt{mefpp\_bpm\_assemble}; the native
recipe reuses its shared C services in process. It consumes only the
completed detector FITS/ASDF artifacts; it never reads raw frames or repeats
characterization. The routine \texttt{mef\_bpm\_mef\_assemble} shares the bias
assembler's bounded byte copier and exclusive sibling-file publication. The
original bias one-extension contract remains separate.

The final primary has no image data and retains the explicitly chosen reference
detector's metadata. Detector masks occupy HDUs $1,\ldots,N$ in catalogue order.
All diagnostic planes then follow in detector and original-HDU order: coverage,
sample count, new flags, selection, and the available prior flags or selection.
Each extension records \texttt{DETID} and \texttt{EXTVER}=configuration slot+1.
Mask \texttt{EXTNAME} is the detector ID; diagnostic names retain their plane
role. Pixel encodings, geometry and every padded data byte are copied unchanged.
The final basename replaces \texttt{ORIGFILE}; stale header checksums are removed,
while data checksums remain valid for unchanged image payloads.

The routine \texttt{mef\_bpm\_assembly\_qc\_write} uses the qualified C ASDF
mapping interface. It joins product measurements, input participation, per-input
measurements and calibration HDU bindings, without recalculating any value.
Calibration records are joined by their original file IDs in first-encounter order.
Shared IDs require identical metadata and collect detector bindings; distinct
masters or masks remain separate records with their original source HDUs.
Only the final product identity, mask output HDUs and references to the source
product ID are remapped. Each complete original detector ASDF is retained as
text evidence, together with the explicit source/output image-plane map and the
recipe snapshot. The final container is self-contained: the saved reader needs
neither the source detector artifacts nor raw files. Metadata is bounded; there
is no all-detector pixel cube. The existing 64 KiB copy buffer is reused.

The independent reader entry point is\par
\texttt{pycavi\_bpm\_linearity\_assembly.read\_product}.\par
It validates the common schema and checks every joined measurement and binding
against the embedded original records, including the permitted identity/HDU
remapping. Native FITS readback checks layout before exclusive publication;
a separate independent comparison checks every final padded image payload.

Historical calibration locations need not be rewritten in their original ASDF
records. Explicit recipe \texttt{calibration\_bindings} declare the original
location, a copy below the project's calibration root, and the preserved SHA256.
Only master/BPM locations are rebound; HDUs, asset IDs, raw paths and scientific
settings remain fixed. Admission compares the declared digest with the original
archive; batch verification checks the actual copied bytes. Native preparation
embeds both the unchanged source graph and these declarations. Its saved reader
checks that the context changed only the declared locations. Project preparation
copies and verifies calibration bytes without decoding pixels or running a
reduction. A conflicting fingerprint is refused, never adopted as a new baseline.

\texttt{read\_manifest} verifies joined ASDF hashes and source/detector mapping
after relocation, without FITS pixels or native commands. FITS integrity rechecking
is explicitly false for this metadata reader; independent image comparison remains
necessary. The C publication path passed its synthetic Mac gate at revision
\texttt{6f3eaaf}. The CCD65 saved-product inspection and Viewer plots have since passed owner
inspection; extension to the full detector cohort remains pending.

\section*{Native recipe: structure and ownership}
The native entry point is
\path{mefpp2/ins/mef/recipes/mefpp_bpm_linearity.c}.
Like \path{mefpp_bias.c}, its visible order is initialize/start,
prepare/admit/begin, serial detector loop, verify/publish/complete, and one
failure/report/destruction path. Both use \texttt{mef\_recipe\_run}; the recipe
owns no all-detector image cube. There are no new estimators or changed
populations in this migration.

The authoring TOML selects one \texttt{native\_recipe} executable and exact
source revision. The assembly table selects the reference detector; child
executables are not configured in this form. The original per-stage form remains
supported for retained records. Mixing the two execution forms is refused.
Project TOML remains the sole owner of shared directory roots.

Pycavi admits archived dependencies, copied-calibration fingerprints and detector
controls, then freezes native bindings in orchestration. C copies the frozen
metadata into the product tree. Bindings declare ordered paths, HDUs and SHA256
identities; they do not introduce alternative scientific settings. Native execution is one command:
\begin{quote}\small\ttfamily
mefpp\_bpm\_linearity\_recipe cal bpm-linearity\par
--config RECIPE.toml --bindings NATIVE.toml --qc false
\end{quote}
Given admitted bindings, this command runs without Pycavi, Python or a shell.
Historical archive-graph resolution remains a metadata-authoring step.

\texttt{prepare} reads the authoring recipe/project/bindings and expands only the
single captured start timestamp. The BPM handoff derives its whole-second
precision from that same instant. \texttt{admit} checks roots, detector order,
calibration consistency, fresh destinations and source fingerprints.
\texttt{begin} creates output/work/log directories and copies frozen metadata,
without copying raw images. \texttt{process} ingests calibrations and frames once,
creates a BPM only when no prior BPM is supplied, then measures linearity from
the same cube. The detector owner releases its buffers after both consumers.
Raw flat buffers and two reference biases remain available for the established
four-plane populations and physical saturation checks; other bias image buffers
are released after their row traces are captured. The supplied master is loaded
once and never scan-corrected again. The current historical-archive admission
contract requires a verified existing master; bias-free archive admission is
not introduced by this refactor.

\texttt{verify} requires a preparation ASDF for every detector and BPM FITS/ASDF
only for created masks. \texttt{publish} assembles newly created BPMs; an explicit
reference must belong to that subset. An all-supplied-mask run records
\texttt{final\_mef\_state=not\_requested}. The receipt records effective QC mode,
per-detector skip decisions and ingestion/correction counters. Shared-cube BPM
ASDF context stores pair-consistency and coverage assessments without changing
their thresholds or fitting population. Numerical/structural failures still fail
the command and retain available evidence. No scientific result is recalculated
during final assembly or saved reading.

Shared inputs are hashed once before and once after the complete batch; between
stages only device/inode/size/mode/nanosecond-mtime identity is checked. The final
content check also detects restored-timestamp edits. SHA256 uses the standard
FIPS 180-4 construction with a 64 KiB read buffer. On macOS the system
\href{https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/CC_SHA256_Update.3cc.html}{CommonCrypto incremental SHA256 API}
is used; other hosts retain the portable implementation, with the same known-answer
checks. This avoids replacing the Mac hash provider with a scalar C implementation. Exact output hashes are stored
in \texttt{native-recipe.toml}. A successful receipt also records measurement-only
state and input preservation; command success additionally requires zero exit.
Failed work remains available. Pycavi independently reads native ASDF and checks
its settings/bindings before writing the familiar combined manifest; it does not
complete or publish QC.

\section*{Native recipe source map}
Stable comment landmarks connect the entry point and C helpers to this section.
Helpers live under \path{mefpp2/ins/mef/common/}.
\begin{enumerate}
\item \texttt{BPM-LINEARITY-ADMISSION}.\par
Sources: \path{mef_bpm_linearity_config.c},
\path{mef_bpm_linearity_inputs.c} and
\path{mef_bpm_linearity_bindings.c}. They admit roots, detector bindings,
frozen dependencies and raw/calibration transport paths. Preparation and BPM
must use the same ordered flat paths/HDUs and native configuration.
\item \texttt{BPM-LINEARITY-DETECTOR-LOOP}.\par
The entry point calls \path{mef_bpm_linearity_process.c} serially,
owning ingestion, optional candidate creation, then linearity measurements.
\item \texttt{BPM-LINEARITY-INGESTION}.\par
\path{mef_detector_cube.c} owns calibration loads, unique path/HDU image planes,
active images and physical row traces. Consumers never destroy borrowed planes.
\item \texttt{BPM-LINEARITY-CANDIDATE}.\par
The same helper calls \path{mef_bpm_command_from_cube} unless a mask was supplied. Fitting remains in
\path{mef_cal_bpm.c} and \path{detector_response.c}.
\item \texttt{BPM-LINEARITY-MEASUREMENTS}.\par
The process helper calls \path{mef_linearity_prepare_from_cube}. Statistics
remain in the preparation/files/pairs kernels mapped earlier; correction is
performed only during ingestion.
\item \texttt{BPM-LINEARITY-PUBLICATION}.\par
The entry point calls \path{mef_bpm_linearity_products.c}:
final MEF assembly and the unchanged native ASDF join.
\item \texttt{BPM-LINEARITY-PRESERVATION}.\par
The products helper and \path{mef_bpm_linearity_hash.c} check streaming
identities and publish the exclusive completion receipt.
\end{enumerate}
The Python metadata/call boundary is
\texttt{pycavi\_bpm\_linearity\_native\_recipe.py}; it contains no detector-stage
execution loop. The focused Mac qualifier builds the coordinator and affected BPM probe, then
checks supplied-mask QC modes and candidate creation with independent ASDF readers.
Local numerical/FITS checks with a labelled test writer do not qualify native
ASDF or observational behavior. Those gates remain mandatory before selection.
